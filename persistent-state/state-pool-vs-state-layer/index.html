vLLM persistent state · design comparison · 2026-11-20

State pool vs state layer

The Nemotron ASR streaming plugin runs on Lucas Wilkinson's draft pdtgct/vllm#6 and gives the same final transcripts as on vllm#67374: all 200 LibriSpeech utterances match on one A40. Five gaps in the draft need core changes before the plugin can depend on it.

#67374 keeps per-session state that tokens cannot rebuild in a state pool with its own scheduler, page handles and release fence. PR 6 keeps the same state in a Mamba layer that MambaManager allocates, plus one flag, ManagerConfig.recomputable.

2026-11-23 · Production design

The production design keeps PR 6's state layer and closes each gap with a stated rule

The rules are EARS specs with the prefix PSTATE. The implementation is pdtgct/vllm branch pstate-impl-20261122 at f24c53bca8: upstream main 842f74fa8d plus PR 6's net diff, the hooks-only re-cut of #67583 and the B2 fix, +1,045 / −56 lines under vllm/ in 32 files. No commit after 7ba8f7d403 has run on a GPU. The rest of this page records the 2026-11-20 analysis that led to this design.

Settled rules:

  • The engine core marks the output that ends a state stream (EngineCoreOutput.terminal). The frontend ends a stream only on that mark.
  • State streams use DELTA output only. CUMULATIVE assembly belongs above the engine.
  • AsyncLLM refuses these sampling options on every input of a state stream: n > 1, stop strings, penalties, bad_words, structured outputs, prompt_logprobs, thinking_token_budget and custom logits processors.
  • AsyncLLM bounds pending inputs per stream with credits (max_pending_stream_inputs, default 8), not with errors.
  • An internal request id joins the external id, the client index, a per-instance nonce and a counter.

Duplex readiness (under review)

vLLM-Omni's orchestrator drives each stage's engine core through StageEngineCoreClient, not AsyncLLM. The revision therefore splits the design into an engine-core contract and AsyncLLM policy. It adds core admission for an opening ADD that had no admit_stream call, a capacity report, and the declared resumable max_tokens stop. Two independent reviews returned changes required:

  • An empty continuation from a client that bypasses AsyncLLM fails an assert in the scheduler and stops the engine core. Core needs its own rule that ends that stream with an error.
  • An opening ADD that reuses a held request id merges into the held stream. Core must refuse it.
  • Core processes an explicit abort without publishing a terminal output, so a client that waits for the terminal mark can wait forever.
  • Admission should ride the opening ADD, which checks and reserves capacity in one step. The capacity report repeats max_num_active_reqs, which is fixed at startup.
  • Unique ids and the pending-input bound hold only for clients that follow a stated client protocol.

Both reviews passed the declared resumable max_tokens stop (TURN-012). Next: revise the rules for these findings, add tests and code for the duplex rules, then run one A40 round.

4 · Lifecycle

One streaming session

A /v1/realtime session is one resumable request that receives its audio in several inputs. Both designs keep the page while the session is parked. They differ in what the next input does and in when a closed session's page goes to another request.

5 · Release

Release fence

A page is safe to reuse once nothing can still write to it for its previous owner. When every state write runs on the runner stream, CUDA runs step N+1 only after step N. The #67374 fence covers writes on other streams, which a model must register.

6 · Session length

A #67374 request does not grow across inputs; a PR 6 request grows with each one

StateScheduler replaces the prompt with each input, and the page carries the history. PR 6 keeps upstream's session accounting: _update_request_as_session appends each input and every kept output token to the prompt, and drops an update that would exceed max_model_len, with a warning (scheduler.py L1968–L2011 at main 07e4d6b957).

At --max-model-len 77000, with about one token plus the label tokens per 320 ms chunk, the token limit allows hours of audio. Host memory and per-turn work run out first; B3 gives the figures and the fix.

7 · Model code

What the model writes

Both snippets are abridged from the stub model my_persistent_state.py in the test plugin.

#67374: declare a page, bind rows each step

# model class
supports_persistent_state = True
spec = PersistentStateSpec(
    descriptors=(
        PersistentStateDescriptor(
            "count", (1,), torch.int64, 0, 8, torch.zeros),
        ...),
    page_size_bytes=page_bytes)
self.state = PersistentStateLayerBase(spec, ...)

# ModelState.prepare_inputs, every step
rows = self.state_slots.bind_rows(
    STATE_LAYER, request_ids, handles)
count_pool = rows.component_pools["count"]
slot_indices = rows.slot_indices_cpu

PR 6: a Mamba layer that reads its metadata

# MambaBase layer
mamba_type = MambaAttentionBackendEnum.SHORT_CONV
def get_kv_cache_config(self, vllm_config):
    spec = MambaSpec(
        shapes=((1,),), dtypes=(torch.int64,),
        block_size=vllm_config.model_config.max_model_len,
        mamba_type=self.mamba_type)
    return MambaManager.layer_config(
        spec, recomputable=False)

# forward
md = get_forward_context().attn_metadata[self.prefix]
slots = md.state_indices_tensor_p[:md.num_prefills]
totals[slots] = totals[slots] * md.has_initial_states_p + ...

#67374 writes each component's initial value when a page gets a new generation. PR 6's MambaManager does not zero new pages (zeroes_new_blocks = False), so the model applies has_initial_states_p itself; the flag is false when the request has no computed tokens. The flag does not suffice for the plugin, whose first step does not write every state, so the port also initializes each new page (B7).

9 · Core gaps

Five gaps need a core change before the plugin can depend on PR 6

B1 to B5 need core changes; B6 and B7 are behaviour changes to settle. B1, B2, B4 and B6 come from reading the source; the round did not exercise them.

IDGapEffectFixStatus
B1No per-request failurePR 6 deletes StateCompletion, which #67374 uses to end one request with an error. A failed plugin row now raises RuntimeError; the engine core treats the exception as fatal, and every client's request fails.Add a core path that fails one request from the model, as fail_requests does in #67374.Open
B2Worker request rows can run outA resumed session leaves num_waiting_for_streaming_input while it still holds its page and worker request row. If the scheduler skips that session in a step, the admission check (scheduler.py L1116–L1121) can admit another request. The budget-fit pool gives the new request a page, but no worker request row is free. The worker's assertion (states.py L99) then fails, and the engine stops.Count every request that holds a worker request row in the admission check, or cap the pool at max_num_seqs + 1 pages.Open
B3Session history grows without bound_update_request_as_session appends each input to the prompt, and the scheduler keeps every audio chunk of the session: about 20 KiB per 320 ms chunk, or about 225 MiB per session-hour. Each turn re-sends the cumulative prompt and every feature record, so the work per turn grows with the session's length. max_model_len is the hard limit.Trim consumed history in _update_request_as_session when every KV group is recomputable=False, keeping one computed token (566ef9259f). The trim restarts positions at 1 each turn. The plugin is safe only because its forward ignores positions, so a general version needs a contract on positions and sampling history.Fix on PoC branch
B4No stream admission#67375 does not rebase onto PR 6, because its logic reads the deleted state scheduler. Without admission, a session opened beyond capacity waits with no transcript. /v1/realtime has no timeout, so a parked session keeps its page until its client disconnects, and max_num_active_reqs idle clients block every new session. A page reserved before any input would not count as held, because _holds_kv_blocks tests num_computed_tokens > 0.Build admission and idle reclaim on MambaManager, with deadlines for streams that are never fed, parked idle or draining.Open
B5Model hooks not in PR 6#67583's capture and lifecycle hooks apply to PR 6 without conflict; its state-pool parts do not. Without a warmup skip for state that tokens cannot rebuild, core warmup sends the plugin synthetic multi-token prefills, which the plugin refuses. On build B the ported hooks capture the plugin's encoder and decoder graphs (1.51 GiB).Rebase #67583 without its state-pool parts, and key the warmup skip on recomputable=False, as build B does.Fix on PoC branch
B6A length stop parks the sessionPR 6 deletes ends_stream. A turn that stops at max_tokens now parks, and the next input continues from mid-turn state. #67374 ends the session on any stop other than EOS.Choose one rule for a turn that stops on length: end the session, as #67374 does, or park it, as PR 6 does.Open
B7New pages are not initializedMambaManager does not zero new pages (zeroes_new_blocks = False), and core's block zeroer skips state pools. A reused page keeps every byte its previous owner wrote that the new owner's first step does not overwrite. The port zeroes the page and writes its initial values in the forward, on the runner stream.Document that the model initializes new pages, or zero new pages when recomputable=False.Open

10 · Plugin changes

The plugin declares one Mamba layer and drops the features PR 6 cannot carry

The port declares its state as one MambaBase layer with one SHORT_CONV MambaSpec and needs no state-pool code from core. 11 · Claims that hold

PR 6's claims that hold for the plugin

  • Page identity and freshness are equivalent: block_ids[0][0] is stable for a request's life, and num_computed_tokens == 0 matches the metadata builder's has_initial_states_p.
  • The plugin needs no release fence under synchronous scheduling (see Release fence).
  • Budget-fit sizing works with the plugin's graphs resident, because core sizes the pool after graph capture (G4).
  • The preemption raise cannot be reached in the plugin's layout: one state group in mode none, block_size >= max_model_len, no speculative decoding and no KV connector.
  • Core's /v1/realtime hook works with the port: 16 of 17 tests pass, and the one failure is the dropped session factory.
